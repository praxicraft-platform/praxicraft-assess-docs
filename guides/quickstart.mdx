Two paths. Pick the one that matches your role.

## Path A: Dashboard (recruiting / ops)

No API key. No terminal.

### Option 1: Jobs first (recommended)

<Steps>
 <Step title="Sign in to Assess">
 Open the [Assess dashboard](https://assess.praxicraft.com/assess).
 </Step>
 <Step title="Create a job">
 Go to [Jobs](https://assess.praxicraft.com/assess/jobs) → **New job**. Pick a hiring squad, write the description, and optionally link an assessment or pipeline.
 </Step>
 <Step title="Publish and review applicants">
 Publish the job. Candidates apply from your careers URL. On the job’s Candidates tab, screen, advance, or reject. Advance sends them toward assessment when configured.
 </Step>
</Steps>

Details: [Jobs & applications](/guides/jobs) · [Screening](/guides/screening).

### Option 2: Assessment-only invite

<Steps>
 <Step title="Create or open an assessment">
 Add tasks, set time limit and passing score, then set status to **Active**. Invites fail if the assessment is still a draft.
 </Step>
 <Step title="Invite a candidate">
 Use **Invite** on that assessment. Enter email and name. Assess can send the email for you.
 </Step>
 <Step title="Watch for completion">
 When they finish, open **Results** on the assessment.
 </Step>
</Steps>

Want Greenhouse, Slack, or spreadsheets to update themselves? Ask an engineer to follow Path B, or use [n8n](/integrations/n8n) / [Automations](/integrations/automations).

## Path B: Public API (engineers)

Hire in the same order as the product: **jobs → applications**, or skip to assessments if you already source elsewhere.

OpenAPI / ReDoc list **Jobs first**: [API Reference](/guides/api-reference) · [live ReDoc](https://assess.praxicraft.com/api/v1/public/redoc/).

### Prerequisites

- Organisation on **Starter** or above (Free cannot create API keys)
- An owner, admin, or [developer](/guides/roles) role (recruiters cannot mint keys)
- For jobs: a hiring squad UUID (`team_id`)
- For invites: an **active** assessment

<Steps>
 <Step title="Create an API key">
 Open [Assess → Developer → API Keys](https://assess.praxicraft.com/assess/api), create a key, and copy it (shown once). Live keys start with `ct_live_`; switch the dashboard to **Test** to mint `ct_test_…`.

 Prefer least-privilege [scopes](/guides/scopes). Empty scopes grant full access (legacy). For jobs automation use `jobs:read`, `jobs:write`, `applications:read`, `applications:write`.
 </Step>

 <Step title="Set your environment">
```bash
export PRAXICRAFT_API_KEY="ct_live_xxxxxxxxxxxxxxxx"
# Optional override (default: https://assess.praxicraft.com)
# export PRAXICRAFT_API_BASE_URL="https://assess.praxicraft.com"
```
 </Step>

 <Step title="List jobs (or create one)">
```bash
curl -sS https://assess.praxicraft.com/api/v1/public/jobs/ \
 -H "Authorization: Bearer $PRAXICRAFT_API_KEY"
```

 Create (draft) requires `team_id` / `squad_id`, then `POST /jobs/{key}/publish/`. Full table: [Jobs](/guides/jobs).
 </Step>

 <Step title="List or create applications">
```bash
curl -sS "https://assess.praxicraft.com/api/v1/public/applications/?job=YOUR_JOB_SLUG" \
 -H "Authorization: Bearer $PRAXICRAFT_API_KEY"
```

 Advance above-threshold people with `POST /applications/{id}/advance/` (does **not** auto-invite everyone who applies).
 </Step>

 <Step title="Optional: invite to an assessment">
 Safe to retry: same email on the same assessment returns the existing invite. Default `send_email` is `false`. Set `true` to have Assess email them.

```bash
curl -sS -X POST \
 "https://assess.praxicraft.com/api/v1/public/assessments/YOUR_SLUG/invites/" \
 -H "Authorization: Bearer $PRAXICRAFT_API_KEY" \
 -H "Content-Type: application/json" \
 -d '{
 "email": "candidate@example.com",
 "name": "Jane Doe",
 "send_email": true
 }'
```

 Save **`invite_token`** from the response.
 </Step>

 <Step title="Fetch the result">
```bash
curl -sS \
 "https://assess.praxicraft.com/api/v1/public/invites/INVITE_TOKEN/result/" \
 -H "Authorization: Bearer $PRAXICRAFT_API_KEY"
```

 In production, prefer [webhooks](/guides/webhooks) (`assessment.completed`, `application.advanced`, …) instead of polling.
 </Step>
</Steps>
